# 자료 화면

## 구조

```
assets/
  shared/          여러 편에서 재사용하는 도식 (빈틈 도식, 지질시대표 등)
  <EP>/shots.yaml  편별 배정표 — 어느 큐에 무엇을 깔지
  <EP>/*.png       그 편에서만 쓰는 자료
```

## 쓰는 법

1. `python3 tools/produce.py EP0XX` → `assets/EP0XX/shots.yaml` 뼈대 생성
   (이미 있으면 **덮어쓰지 않습니다.** 채워둔 경로가 날아가지 않습니다)
2. `file:` 에 이미지·영상 경로를 넣습니다 (리포 루트 기준)
3. `python3 tools/render.py EP0XX` → 해당 구간 배경으로 합성

```yaml
- cue: 9
  at: 17.8            # 참고용 — 실제 타이밍은 렌더가 SRT 에서 다시 찾습니다
  until: 20.8
  line: 빈틈을 하나 메우면 빈틈이 둘로 늘어납니다.   # 이 컷이 붙은 자막
  screen: '"무한 후퇴 요구" — A···C 사이에 B를 넣자 빈틈이 둘로 갈라지는 도식'
  file: assets/shared/gap-2.png
  fit: cover        # cover(가득 채우고 잘라냄) | contain(전체을 보이게)
```

### `at` / `until` 은 참고용입니다
렌더는 `cue` 번호로 **현재 SRT** 에서 타이밍을 찾습니다.
TTS 가 SRT 를 실측으로 다시 쓰기 때문에 yaml 의 숫자는 금방 낡습니다.

### `line:` 을 지우지 마세요
대본을 고쳐 큐가 다시 쪼개지면 **번호는 멀쩡한데 가리키는 자막만 바뀝니다.**
CN01 에서 Nature 도식이 교육부 대사 위에 깔렸는데,
번호상으로는 정상이라 영상을 눈으로 볼 때까지 아무도 몰랐습니다.
`line:` 이 있으면 렌더가 어긋난 컷을 이름 대고 경고합니다.
대본을 크게 고쳤으면 `shots.yaml` 을 지우고 `produce.py` 로 다시 만드는 게 빠릅니다.

### 같은 파일을 연달아 쓰면 한 컷으로 합쳐집니다
한 도식을 여러 줄에 걸쳐 보여줄 때 큐마다 끊으면
경계에서 켄번스 확대가 처음으로 되감겨 화면이 튑니다. 렌더가 알아서 이어 붙입니다.

### 얼마나 채울 것인가
비워두면 그 구간은 단색 배경입니다.
**한두 박자 비우는 건 의도적으로 쓰세요** — 다음 컷을 때리기 전 숨.
하지만 **대부분이 비어 있으면 부실해 보입니다.**
큐 15개에 컷 3개였던 EP001 은 "자료 화면이 비어 있다"는 지적을 받았고,
지금은 15개 중 14개를 채웁니다.

자료가 깔린 구간에만 어둠막이 적용되고, 나머지는 브랜드 색 그대로입니다.

## 도식 생성기

`tools/makediagram.py` 가 `assets/shared/` 의 도식을 만듭니다.
색이나 배치를 고치려면 이 파일만 수정하고 다시 돌리세요.

```bash
python3 tools/makediagram.py
```

세로 영상에 맞춘 배치입니다. 가로형으로 그리면 세로 공간을 버리게 됩니다.

## 제작 규격

- **1080 × 1920** 권장. 다른 비율도 `fit` 으로 처리되지만 잘립니다
- 실질 작업 영역은 **y 230 ~ 1100** 입니다
  - `y < 230` 상단 안전영역 (플랫폼 UI)
  - `y > 1100` 자막 + 어둠막 영역 — **핵심 내용 금지**
- **세로로 쌓으세요.** 가로 한 줄 배치는 폭의 60%만 쓰고 높이를 버립니다
- 색은 브랜드 팔레트를 따르세요 → [02 브랜드](../docs/02-brand.md) §3

### 자주 저지른 실수

렌더해서 눈으로 확인하기 전까지 안 보이는 것들입니다:

| 실수 | 증상 |
|---|---|
| 같은 색 위에 같은 색 글자 | 벽돌색 박스에 벽돌색 글자 → 안 읽힘 |
| X 표시를 글자보다 나중에 그림 | 글자가 가려짐. SVG는 나중에 그린 것이 위 |
| 청록 배경에 벽돌색 캡션 | 대비 부족. 크림 바탕을 깔고 올릴 것 |
| 숫자 폭을 글자수로 추정 | 단위가 숫자에 겹침. 줄을 나누는 편이 안전 |
| 단위 표기 | 와트(W)는 이미 초당 에너지. `W/s` 는 틀림 |

**만들고 나면 반드시 렌더해서 보세요.** 위 다섯 가지는 전부 코드만 봐서는 안 보였고,
PNG로 뽑아 눈으로 본 뒤에야 드러났습니다.

## 자유 라이선스 이미지 받기

```bash
python3 tools/fetchmedia.py search "Tiktaalik roseae"
python3 tools/fetchmedia.py get 3 --ep EP003 --name tiktaalik-restoration
python3 tools/fetchmedia.py credits      # 저작자 표시가 필요한 자료 목록
```

**소스** (둘 다 API 키 불필요)

| 소스 | 강점 |
|---|---|
| **Wikimedia Commons** | 화석·복원도·표본 사진이 가장 풍부. 퍼블릭 도메인 자료 다수 |
| **Openverse** | CC 통합 검색 (Flickr, 박물관 등) |

Pexels·Unsplash 는 넣지 않았습니다 — 일반 스톡이라 "틱타알릭 화석" 같은
과학 소재가 없고, API 키도 필요합니다. 필요하면 키를 받아 소스를 추가하세요.

**상업적 이용·개작이 가능한 라이선스만 자동 승인**합니다 (CC0 / PD / CC BY / CC BY-SA).
NC(비상업)·ND(개작금지)는 경고가 뜨고 `--force` 없이는 받지 않습니다 —
영상에 얹어 편집하고 수익화를 열려면 이 조건이 필요합니다.

받은 자료의 출처는 `assets/CREDITS.yaml` 에 자동 기록되고, 그 다음은 자동입니다:

- `produce.py` 가 CC BY 계열의 **저작자 표시를 고정 댓글에 삽입**합니다
- `claimctl.py validate` 가 **기록 없는 외부 자료를 발행 차단**합니다
- `assets/shared/` 의 자체 제작 도식은 표시 의무가 없어 제외됩니다

직접 넣은 파일은 `CREDITS.yaml` 에 수동으로 추가해야 검수를 통과합니다.

`content/sources.md` 에 이미지 출처도 함께 기록하세요.
분쟁 시 "어디서 가져왔는지 모른다"가 가장 나쁜 상태입니다.
