# 05. 제작 파이프라인

한 편이 아이디어에서 발행까지 가는 경로. **각 게이트를 통과하지 못하면 다음 단계로 못 갑니다.**

```
① 선정 → ② 조사 → ③ 대본 → ④ [게이트1: validate] → ⑤ [게이트2: 원문대조]
   → ⑥ [게이트3: 반대심문] → ⑦ 녹음 → ⑧ 편집 → ⑨ [게이트4: 최종검수] → ⑩ 발행
```

## ① 선정
`python3 tools/claimctl.py calendar --weeks 4` 로 다음 4주 슬롯 확인.
우선순위 → 난이도 순으로 자동 배정됩니다. **초반에는 난이도 1~2만 하세요** —
어려운 편을 초반에 배치하면 완주율이 낮게 시작하고 채널 전체 노출이 눌립니다.

## ② 조사 (편당 2~4시간)
- `claims.yaml`의 `evidence` 항목을 출발점으로 **1차 출처를 직접 열람**
- 새 출처는 `content/sources.md`에 ID를 부여해 등재
- **초록만 읽고 쓰지 않습니다.** 최소한 결론과 방법 절은 읽으세요
- 상대 진영이 이 주제에 어떻게 반박하는지 미리 조사 → `예상 재반박`에 기록

## ③ 대본
`content/scripts/_TEMPLATE.md` 복사 → `EP0XX-slug.md`
- 모든 사실 주장에 `[S-XXX]` 마커
- `예상 재반박` 섹션을 **반드시** 작성 (영상에는 안 들어가지만 댓글 대응의 전부)
- 고정 댓글 블록까지 대본 안에서 완성

## ④ 게이트 1 — 기계 검수
```bash
python3 tools/claimctl.py validate
```
검사 항목: front matter 완결성, claim_id·출처 ID 실재 여부, 본문 마커와 선언 일치,
길이(70초 초과 시 오류), `confidence: active`의 단정 어조, 자책골 표현, 레드라인 표현.

**오류가 하나라도 있으면 녹음하지 않습니다.** 녹음 후 발견하면 재녹음 비용이 발생합니다.

## ⑤ 게이트 2 — 원문 대조 (기계 + 사람)
```bash
python3 tools/attest.py init EP0XX && python3 tools/attest.py check
```
→ [편집 정책](03-editorial-policy.md) §2 2단계
- 인용문을 원문에서 확인. 2차 인용 금지
- 숫자의 단위·오차범위 확인
- 논문 결론이 우리 서술 방향과 실제로 일치하는지

## ⑥ 게이트 3 — 반대 심문 (사람)
대본을 창조론자 입장에서 소리 내어 읽고, `예상 재반박`의 각 항목에 답이 준비됐는지 확인.
**허수아비를 만들지 않았는지**가 핵심 점검 항목입니다.

## ⑦ 녹음
- 조용한 공간, 동일 마이크·동일 거리 유지 (회차 간 음색 일관성)
- TTS 사용 시 **보이스를 절대 바꾸지 마세요.** 일관성이 신뢰도입니다
- 숫자와 학명은 **의도적으로 느리게**. 여기서 빠르면 못 알아듣습니다
- 한 문장씩 끊어 녹음하고 최선 테이크를 고르는 편이 통으로 가는 것보다 빠릅니다

## ⑧ 편집
- 컷: 3~5초마다 화면 전환 (정보 콘텐츠는 전환이 리듬을 만듦)
- **출처 자막은 증거 컷마다 하단 고정.** 없는 컷은 게이트 4에서 반려
- 색 규칙 준수: 창조론 주장 = `--claim`, 검증된 사실 = `--evidence` → [브랜드](02-brand.md) §3
- 번인 자막 56px 이상, 안전영역 준수
- 음량 -14 LUFS

## ⑧.5 제작 패키지 빌드
```bash
python3 tools/produce.py EP0XX
```
`build/EP0XX/` 에 낭독 원고·SRT 자막·샷 리스트·메타데이터·고정 댓글·체크리스트가 생성됩니다.
**⑦ 녹음 전에 빌드하세요** — `narration.txt` 가 녹음 원고이고,
`shotlist.md` 가 편집 작업 문서입니다. → [12 파이프라인](12-pipeline.md) §B

## ⑨ 게이트 4 — 최종 검수
```bash
python3 tools/claimctl.py meta EP0XX   # 체크리스트 출력
```
또는 `build/EP0XX/checklist.md` 사용 (미검증 출처 경고 포함)
체크리스트 전 항목 확인. 특히:
- 음소거로 한 번 재생해 보세요. **소리 없이 이해되면 통과.**
- 아무 프레임이나 캡처해서, 맥락 없이 돌아다녀도 오해 없을지 확인

## ⑩ 발행
- 두 플랫폼 동시, 원본 파일에서 각각 내보내기 (워터마크 금지)
- **발행 즉시 고정 댓글에 출처 전문 게시** — 미루면 잊습니다
- `claims.yaml`의 `status: published`, `episode: EP0XX` 갱신 후 커밋
- 대본 front matter `status: published` 갱신

## 사후 (48시간)
- 댓글에서 반복되는 반론 수집 → `claims.yaml`에 새 주장으로 추가 (E 기둥 소재)
- 사실관계 오류 지적이 있으면 **24시간 내 고정 댓글 정정** → [편집 정책](03-editorial-policy.md) §5

## 소요 시간 (실측 전 추정치)

| 단계 | 시간 |
|---|---|
| 조사 | 2~4h |
| 대본 + 게이트 1~3 | 2~3h |
| 녹음 | 0.5~1h |
| 편집 | 2~4h |
| 발행·사후 | 0.5h |
| **합계** | **7~12.5h / 편** |

주 3회는 **주당 21~37시간**입니다. 이건 취미 규모가 아닙니다.
현실적으로 잡으려면 ①②를 주말에 몰아서 3편치 배치 처리하고,
④~⑩을 평일에 나누는 구조가 낫습니다. → [런칭 계획](07-launch-90days.md)
