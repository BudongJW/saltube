# 15. 업로드 자동화 — 틱톡 API 검토 결과

**결론부터**: 완전 자동 게시는 지금 불가능합니다. **초안함까지는 자동화됩니다.**
마지막 "게시" 버튼은 사람이 틱톡 앱에서 눌러야 합니다.

---

## 1. 틱톡 Content Posting API 는 두 갈래

| | Direct Post | Inbox (초안함) |
|---|---|---|
| 스코프 | `video.publish` | `video.upload` |
| 결과 | 바로 공개 게시 | 크리에이터 초안함으로 전송 |
| **심사 전 제약** | **전부 `SELF_ONLY`(비공개) 강제** | **제약 없음** |
| 사람 개입 | 불필요 | 앱에서 마무리 필요 |

여기가 핵심입니다. **심사를 통과하지 못한 앱이 Direct Post 로 올린 영상은
공개 설정을 뭘로 요청하든 전부 비공개로 강제됩니다.** 아무도 못 봅니다.
심사 전에 Direct Post 를 붙이면 "자동으로 올라가는데 조회수가 0"인
상태가 됩니다 — 실패가 눈에 안 띄는 최악의 형태입니다.

그래서 `tools/uploadtiktok.py` 는 **`video.upload`(초안함)** 을 씁니다.
이쪽은 사람이 직접 게시하므로 심사 제한을 받지 않습니다.

## 2. 심사(Audit)를 받으면 무엇이 달라지나

Direct Post 로 **공개** 게시가 가능해집니다. 대신:

- 심사에 **몇 주** 걸립니다
- 앱의 전체 동작을 보여주는 **데모 영상**을 제출해야 합니다
- 게시 UX 가 틱톡 가이드라인에 맞아야 합니다
  (게시 전 미리보기, 크리에이터가 공개 범위를 고를 수 있을 것 등)
- URL 방식(`PULL_FROM_URL`)을 쓰려면 **도메인 소유 확인**이 필요합니다
  — 파일 직접 업로드(`FILE_UPLOAD`)는 도메인이 없어도 됩니다

혼자 쓰는 채널 하나를 위해 심사를 받을 값어치가 있는지는 별개 문제입니다.
편당 마지막 한 번 탭하는 것과, 몇 주짜리 심사를 맞바꾸는 셈입니다.

## 3. 제약 (공식 문서 기준)

- 액세스 토큰당 **분당 6요청**
- **24시간 내 대기 중인 공유 5건**까지
- 심사 전 앱은 **24시간에 5명**까지만 게시 가능 (우리는 1명이라 무관)
- `upload_url` 은 발급 후 **1시간** 유효

24시간 5건 제한 때문에 `--check` 로 먼저 거르는 게 중요합니다.
잘못된 파일로 시도를 낭비하면 그날 다시 못 올립니다.

## 4. 토큰 발급 절차

이 저장소에서는 할 수 없습니다 — 브라우저 리디렉션이 필요합니다.

1. <https://developers.tiktok.com> 에서 앱 등록
2. **Content Posting API** 제품 추가, 스코프 `video.upload` 신청
3. 리디렉션 URI 등록 (로컬 테스트면 `http://localhost:8080/callback`)
4. 로그인 키트로 인가 → `code` → 토큰 교환
5. 받은 access token 을 환경변수로:

```bash
export TIKTOK_ACCESS_TOKEN='...'
python3 tools/uploadtiktok.py CN01 --check   # 먼저 규격 검사
python3 tools/uploadtiktok.py CN01           # 초안함으로 전송
```

액세스 토큰은 24시간 만료입니다. 리프레시 토큰으로 갱신해야
주기적 자동화가 됩니다 — 지금은 수동 갱신을 전제로 합니다.

> **이 도구는 실제 API 호출로 검증되지 않았습니다.**
> 자격증명이 없어 `--check`(오프라인 검사)까지만 시험했습니다.
> 첫 전송은 반드시 사람이 지켜보면서 하세요.

## 5. 유튜브 쇼츠

YouTube Data API `videos.insert` 는 **심사 없이 공개 업로드가 됩니다.**
틱톡보다 사정이 낫습니다. 다만:

- OAuth 동의 화면이 "테스트" 상태면 **업로드한 영상이 비공개로 잠깁니다.**
  앱을 "프로덕션"으로 올리거나, 본인 계정을 테스트 사용자로 등록해야 합니다
- 할당량: 업로드 1건에 약 1600 units, 기본 일일 할당량 10,000 units
  → **하루 약 6편**. 우리 페이스에는 충분합니다

아직 구현하지 않았습니다. 틱톡 쪽 토큰 발급이 먼저 되면 같은 구조로 붙입니다.

## 6. 중요 — 중국어판이 실제로 닿는 곳

**틱톡은 중국 본토에서 서비스하지 않습니다.** 본토는 같은 회사(바이트댄스)의
별도 앱 **더우인(抖音)** 을 쓰고, 두 앱은 계정도 콘텐츠 풀도 완전히 분리돼 있습니다.
더우인은 중국 휴대폰 번호가 있어야 가입됩니다.
틱톡은 2020년 홍콩에서도 철수했습니다.

그러므로 중국어 영상을 틱톡에 올리면 닿는 곳은:

- **대만** (틱톡 서비스 중)
- **싱가포르 · 말레이시아**
- 그 외 해외 화교권

**중국 본토 시청자에게는 닿지 않습니다.**

여기서 두 가지가 따라옵니다:

1. **번체/간체.** 싱가포르·말레이시아는 간체를 쓰지만
   **대만은 번체(zh-TW)** 입니다. 틱톡에서 가장 큰 중국어권 시장이 대만입니다.
   → **TW01 (번체판)을 따로 만들었습니다.** 대만·홍콩·마카오는 TW01,
   싱가포르·말레이시아는 CN01 을 올리세요.

   번체는 글자만 바꾸는 게 아닙니다. 가장 중요한 건 **`進化` → `演化`** —
   대만 교과서와 학계의 표준 용어이고, `進化` 는 "발전·향상" 뉘앙스가 있어
   학술 맥락에 쓰지 않습니다. **이 단어 하나로 "본토에서 만든 영상"이라는 게
   드러납니다.** 그 외 `報道`→`報導`, `咨询`→`諮詢`, `里`→`裡`, `下属`→`旗下`,
   그리고 《自然》은 `雜誌` 가 아니라 **`期刊`**(학술지)입니다.
2. **"어차피 종교 자유가 없으니 상관없다"는 전제가 성립하지 않습니다.**
   실제로 닿는 대만·싱가포르·말레이시아는 종교 자유가 보장된 곳이고,
   기독교 인구도 적지 않습니다. 편집 정책 §1(종교·신자 비하 금지)이
   한국어판과 똑같이 적용돼야 합니다.

본토를 노린다면 틱톡이 아니라 **더우인 · 비리비리 · 샤오훙수**이고,
셋 다 중국 실명 인증이 필요하며 종교·정치 관련 심의가 별도로 있습니다.
